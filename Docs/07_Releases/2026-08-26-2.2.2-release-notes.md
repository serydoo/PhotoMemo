# MemoMark 2.2.2 (90) 版本更新说明

## 版本与范围

- 版本：`2.2.2`
- 构建号：`90`
- 最近一次 GitHub 推送基线：`c0f11a7aa36b7a3b0107b3e6003214e57376e074`
- 基线时间：2026-08-24 06:49:40 +0800
- 对比范围：`c0f11a7..current working tree`
- 当前状态：`Version Locked; Release Evidence Open`
- 本轮没有提交、推送、上传 TestFlight 或提交 App Store。

本版本整理了最近一次 GitHub 推送之后的 Configuration Center、Apple
Photos 交接、本地恢复、浅色界面体验以及内部产品命名迁移。内部命名迁移
不改变用户工作流，也不作为对外功能宣传。

## 面向用户的变化

### 配置中心更连贯

- Memory Source、Memory Expression、Card Style、Card Layout And Content、
  Photo Description 和 Output Destination 现在沿着同一条配置路径组织。
- Photo Description 和 Output Destination 与 Memory Card 设置放在同一处，
  减少在不同页面之间来回切换。
- 主要区块首次打开时清楚呈现，之后会记住用户的展开与收起选择。
- 长文字、辅助功能字号和窄屏布局继续使用同一套内容层级，避免标题、结果
  和调整操作相互遮挡。

### 从 Apple Photos 分享更容易跟进

- 修复部分真机上从 Apple Photos 分享后，在照片尚未读取前就被错误拦截的情况。
- 分享、处理和 Progress 状态的边界更明确，用户能更容易判断照片已经收到、
  正在处理，还是需要恢复。
- 完整 Live Photo 只有在静态资源、视频资源和配对关系得到确认后，才会以新
  的 Live Photo 返回 Apple Photos。
- 生日、纪念日和倒计时继续保留各自的日常含义，不把不同类型的重要日期混为
  一种表达。

### 中断后更容易恢复

- PhotoKit 保存回执只在对应的 Photos 事务完成后确认，避免尚未保存就显示成功。
- 处理被打断、应用重新打开或持久化暂时失败时，任务状态和恢复信息保持可见。
- 照片选择会使用开始选择时捕获的配置，不会被之后的配置切换悄悄改变含义。
- 记忆对象头像和相册选项的异步结果会检查当前上下文，避免较早的结果覆盖较新
  的选择。

### 轻量的界面整理

- Home、Configuration Center、Progress、Share presentation 和 Card Content
  Editor 的信息层级更加统一。
- Configuration Center 底部 Save / More 操作保持在明确的操作区域内，长页面
  的相邻内容不会被整条模糊背景遮住。
- Card Content Editor 的标题改为输入框左侧的紧凑同行结构，输入框视觉高度收窄；
  空白、文字和模块状态统一使用固定高度的中心光标，插入模块后仍为模块胶囊预留完整高度。
- 修复自定义文字与一个或多个模块混排时的删除定位：退格只删除光标左侧紧邻的
  文字或模块，不会跳到最右侧模块；删除后光标继续留在原来的局部位置。
- 统一文字与模块共用的 TextKit 行盒和上下内边距，避免光标在文字、模块和空白内容
  之间上下摇摆；原生 caret 由固定 `16pt` 高的可视 caret 替代，始终以统一输入面中心
  为垂直基准，空白、文字和模块附件不再分别决定 caret 的纵向位置；多区域标题列与输入
  框边框的间距也收紧，
  保持与极简单区域一致的同行布局。
- 两种现有模块胶囊统一使用同一组尺寸、圆角、边框、图标和间距规范；模块解析失败时保留
  原始表达式并显示同尺寸的可读降级胶囊，不再出现空白模块或失效后内容消失。
- 编辑器复制/粘贴现在保留普通文字、模块身份、模块顺序和照片信息表达式；粘贴到外部应用时
  自动提供纯文本内容。模块插入、结构化粘贴和模块删除也纳入同一套撤销快照，撤销会恢复编辑内容
  与光标位置。
- 本轮同步近期 UI 文件的正式命名和工程引用，保留界面层级、布局常量、状态流
  和交互语义。

### 卡片输出与编辑内容修复

- 修复 Classic White / 基础白 Live Photo 动态输出底部出现黑色空边、底栏内容
  丢失的问题；静态图与动态资源现在使用同一套完整输出几何。
- 修复 Minimal / 极简只显示智能结果、无法显示 Card Content Editor 用户组合内容
  的问题；现在 slot A 是 Minimal 唯一的渲染内容和 Apple Photos 照片说明来源，
  不再借用 Classic White 的 slot D。
- Classic White 与 Minimal 的编辑内容现在分别保存，切换样式不会互相覆盖；保存
  和再次打开后，两种样式的内容都能恢复到各自状态。
- 建立统一的样式内容契约，集中定义每种样式的可编辑区域、渲染区域和照片说明来源，
  为后续 2～3 个自定义区域的 Renderer 留出稳定扩展点。

## 不变的原则

- 照片仍然只在用户设备本地处理。
- 原始照片不会被修改，MemoMark 生成新的记忆照片并保存回 Apple Photos。
- Apple Photos 继续拥有照片库身份和最终保存事务。
- Memory Engine、Layout Engine、Renderer、Export、Share Extension 和持久化
  配置的职责边界不变。
- 应用不要求账号登录，核心照片流程不依赖云端服务。

## 内部工程整理

- 当前工程入口统一为 `Source/MemoMark/MemoMark.xcodeproj`。
- App、iOS、Share Extension、Widget、测试和 QA 的内部类型、文件名、target、
  scheme 与模块引用已统一为 MemoMark 命名。
- 已发布 Bundle ID、App Group、UserDefaults 键、后台任务标识、StoreKit 商品
  ID、旧 `photomemo://` URL 解析和诊断协议保持兼容。
- 这部分是内部维护性整理，不改变用户可见功能或既有数据。
