## 面向用户的变化

### 配置中心更连贯

- Memory Source、Memory Expression、Card Style、Card Layout And Content、Photo Description 和 Output Destination 现在沿着同一条配置路径组织。
- Photo Description 和 Output Destination 与 Memory Card 设置放在同一处，减少在不同页面之间来回切换。
- 主要区块首次打开时清楚呈现，之后会记住用户的展开与收起选择。
- 长文字、辅助功能字号和窄屏布局继续使用同一套内容层级，避免标题、结果和调整操作相互遮挡。

### 从 Apple Photos 分享更容易跟进

- 修复部分真机上从 Apple Photos 分享后，在照片尚未读取前就被错误拦截的情况。
- 分享、处理和 Progress 状态的边界更明确，用户能更容易判断照片已经收到、正在处理，还是需要恢复。
- 完整 Live Photo 只有在静态资源、视频资源和配对关系得到确认后，才会以新的 Live Photo 返回 Apple Photos。
- 生日、纪念日和倒计时继续保留各自的日常含义，不把不同类型的重要日期混为一种表达。

### 中断后更容易恢复

- PhotoKit 保存回执只在对应的 Photos 事务完成后确认，避免尚未保存就显示成功。
- 处理被打断、应用重新打开或持久化暂时失败时，任务状态和恢复信息保持可见。
- 照片选择会使用开始选择时捕获的配置，不会被之后的配置切换悄悄改变含义。
- 记忆对象头像和相册选项的异步结果会检查当前上下文，避免较早的结果覆盖较新的选择。

### 卡片内容编辑更稳定

- 内容编辑器的标题与输入框改为更紧凑的同行布局，空白、纯文字、中文标点和文字与模块混排均保持稳定的输入高度与光标位置。
- 文字、模块和光标使用统一的输入行盒；在模块前、模块后、模块夹中、删除模块或重新插入模块时，文字不会上下跳动。
- 自定义文字与一个或多个模块混排时，退格只删除光标左侧紧邻的文字或模块，不会跳到最右侧模块；删除后光标继续留在原来的局部位置。
- 模块胶囊统一使用同一组尺寸、圆角、边框、图标和间距规范；模块暂时无法识别时仍保留清晰的可读内容，不会变成空白。
- 复制和粘贴内容时保留普通文字、模块身份、模块顺序和照片信息表达式；粘贴到外部应用时提供纯文本内容。
- 模块插入、结构化粘贴和模块删除纳入同一套撤销快照，撤销会恢复编辑内容与光标位置。

### 卡片输出与样式连续性

- 修复 Classic White 动态照片输出底部出现黑色空边、底栏内容丢失的问题；静态图与动态资源使用同一套完整输出几何。
- Minimal 卡片现在会准确保留你在内容编辑区域组合的文字，并同步写入照片说明。
- Classic White 与 Minimal 的编辑内容分别保存，切换样式不会互相覆盖；保存和再次打开后，两种样式的内容都能恢复到各自状态。
- 建立统一的样式内容约束，为后续卡片样式和编辑器保持一致的内容映射与扩展边界。

### 照片处理与兼容性

- 照片资源名称读取兼容不同版本的 Xcode/Photos 工具链，避免归档环境差异阻断正式构建。
- 延续本地处理、原始照片保护和 Apple Photos 保存回读的可靠性修复。

## 不变的原则

- 照片仍然只在用户设备本地处理。
- 原始照片不会被修改，MemoMark 生成新的记忆照片并保存回 Apple Photos。
- Apple Photos 继续拥有照片库身份和最终保存事务。
- Memory Engine、Layout Engine、Renderer、Export、Share Extension 和持久化配置的职责边界不变。
- 应用不要求账号登录，核心照片流程不依赖云端服务。
