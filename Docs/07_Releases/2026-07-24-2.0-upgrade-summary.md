# MemoMark 2.0 版本优化升级总结

日期：2026 年 7 月 24 日

发布版本：`2.0 (47)`

同步范围：`863b0c9c`、`40555397`、`7cf36071`

对比基线：`0b932f34`（上上次同步前的 GitHub 基线）

变更规模：148 个文件，12,092 行新增，761 行删除

## 结论

本轮从 1.7 的 UI 与后台稳定性收口开始，经过 MemoMark+ 初版接入，最终完成 2.0 发布候选修正。当前版本保持 MemoMark 的本地优先架构，不上传照片、不修改原图，商业逻辑未进入 Renderer、Metadata Engine、Memory Engine 或 Layout Engine。

GitHub `main` 用于触发 Xcode Cloud；本次合并后，Xcode Cloud 应在 `2.0` 产品版本下自动生成下一构建号，预计为 build `48`。本地项目中的 BrandMark 研究仍未定稿，不属于 2.0 发布范围，也不进入本次 GitHub 同步。

## 一、1.7 UI 与可靠性收口

对应提交：`863b0c9c Close 1.7 UI and reliability follow-up`

- 将 Configuration Center 的内容边界、卡片层级、排版、间距、设计令牌和语义图标延伸到主程序相关界面。
- 将 Share Extension 整理为适合紧凑半屏的原生层级，同时保留 Apple Photos -> Share -> MemoMark -> Processing -> Notification -> Apple Photos 工作流。
- Share 请求仅在成功入队或明确终止后确认，避免请求在持久化失败时提前消失。
- UserDefaults 队列写入增加同步、读回验证和错误暴露；队列损坏不再静默变为空队列。
- 加强后台任务持久化、恢复、取消、源文件生命周期和诊断信息。
- 静态照片与 Live Photo 的 PhotoKit 保存串行化，并增加任务级幂等标识，降低重复写图库风险。
- 完成 Settings、Home、Output、Task 等页面的原生交互、窄屏布局和辅助功能优化。

## 二、MemoMark+ 初版商业化

对应提交：`40555397 Add MemoMark+ purchase experience`

- 建立免费 200 张成功成长记录的本地额度模型。
- 免费用户单批最多处理 20 张，MemoMark+ 单批最多处理 40 张，并在较大批次中保留设备负载提示。
- 接入 StoreKit 2 非消耗型永久买断商品：`com.serydoo.PhotoMemo.iOS.memomarkplus.lifetime`。
- 增加购买、恢复购买和 Apple 兑换入口；交易、退款、家庭共享与购买记录由 Apple 管理。
- 增加首批记录者计划、MemoMark+ 购买页、设置入口、购买成功反馈和金色身份徽章。
- 额度只在新资产成功写入 Apple Photos 后扣减；预览、失败、取消、保存失败和重复完成回调均不计数。
- 保留本地 Credit Ledger，为初始额度、版本成长礼、成功扣减和防重复领取提供可追溯记录。

该提交首次将商业化链路带入正式分支，随后暴露出 PhotoKit 完成判定、命名延续、环境隔离和文案本地化等需要发布前修正的问题；这些问题已在 2.0 发布候选中处理。

## 三、2.0 发布候选修正与升级

对应提交：`7cf36071 Prepare MemoMark 2.0 release`

### Apple 托管商业边界

- 当前阶段只保留 MemoMark+ 永久买断，不上线次数包，也不建设兑换服务器或自有商业后台。
- TestFlight 使用 Sandbox 交易，并提供临时 MemoMark+ 体验；同一套构建提交审核后自动使用 Production 商店环境。
- Production、Sandbox 和本地 Xcode 测试环境的权益与额度隔离，避免测试状态污染正式用户数据。
- 每个大版本可向免费用户追加一次成长礼；2.0 规则为追加 100 张，不重置已有余额。
- Promo Code 或 Offer Code 兑换成功后由 StoreKit 权益统一识别；家庭共享成员不会被自动标记为首批记录者。

### 多语言与设置界面

- 建立中文与英文的 MemoMark 语言模型及 `Localizable.strings` 资源。
- 统一购买页、权益状态、额度、批量提醒、恢复购买、兑换入口、交易错误和成功反馈文案。
- 优化英文 Memory Anchor 输出，使年龄、倒计时和相对时间表达符合英文自然语序。
- 将设置中的语言模块移动到版本信息之前。
- 扩充设置内的反馈渠道，同时保持首页反馈入口和现有内容不变。
- 版本信息统一读取 Bundle 的产品版本与构建号，显示为 `2.0 (47)`，不再把 Xcode Cloud 构建号拼进产品版本号。

### PhotoKit 与后台队列稳定性

- 修复任务卡在 99% 的主要路径：移除主线程上的完整图库扫描。
- 保存完成验证改为本地保存回执与 `fetchAssets(withLocalIdentifiers:)` 精确查询，减少大图库阻塞和界面假死。
- 加强静态照片和 Live Photo 的完成判定、队列恢复、重复回调防护、保存诊断和失败路径。
- Live Photo 队列回归测试改用确定性的图库保存依赖，避免真实 PhotoKit 异步时序造成测试假失败。
- 后台任务可以较慢完成，但不得因为新增任务、失败重试或图库验证阻塞主程序。

### 输出文件命名

- 恢复以原始照片文件名为基础的输出命名。
- 同一原图多轮处理使用持久编号自动递增，例如 `IMG_1642 (1)`、`IMG_1642 (2)`。
- 静态照片与 Live Photo 共用相同的编号规则，避免重启、重试或多轮处理后退回异常名称。

### App Store 发布材料

- 补充 MemoMark+ App Store Connect 设置说明。
- 补充 App Store 截图和 App Preview 的设计与实施方案。
- 购买价格由 StoreKit 的本地化价格提供，不在 UI 中硬编码人民币价格。
- 购买页继续遵循 Apple 原生、克制、家庭记忆导向的视觉语言，不使用倒计时或剩余名额等促销表达。

## 架构核对

- Commerce 只观察 Apple Photos 成功保存结果，不接管渲染、导出或布局决策。
- Renderer、Metadata Engine、Memory Engine、Presentation Engine 和 Layout Engine 的既有职责未被商业化逻辑改变。
- Share Extension 只读取必要的本地商业快照，不直接承担 StoreKit 交易或网络查询。
- Apple 负责交易、恢复、兑换、退款、税务和家庭共享；MemoMark 只维护本地额度 Ledger 与界面状态。
- 日常工作流仍为 Apple Photos -> Share -> MemoMark -> Processing -> Notification -> Apple Photos。

## 发布后重点观察

- Xcode Cloud 是否由 `main` 合并自动触发，并将构建号从 47 递增到 48。
- App Store Connect 中永久买断商品是否与 2.0 App 版本一并提交审核。
- TestFlight 中购买、恢复、兑换、200 张边界、20/40 张批量限制与临时体验是否符合预期。
- Production 发布后 StoreKit 是否返回正确的本地化商品信息和正式权益。
- 大图库、Live Photo、多任务连续新增和后台恢复场景中是否仍存在 99% 停留或重复保存。

- 尚未冻结的 Renderer 或新 Preset 研究不进入 2.0 发布候选。
- 次数包、自建兑换服务、自有用户后台和云端照片能力不属于当前商业模型。
