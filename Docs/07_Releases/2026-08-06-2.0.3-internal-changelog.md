# MemoMark 2.0.3 (70) 内部变更记录

状态：`Version Locked; Release Evidence Open`

整理日期：`2026-08-06`

同步基线：`2.0.2 (69)`，提交 `fe201be115e0a86dc944ac9f01a1178c086c34f5`

目标版本与构建号：`2.0.3 (70)`

## 版本定位

本轮是 MemoMark V4 阶段的一次有边界的产品体验与工程可靠性更新。工作集中在五处：统一时间锚点的日历日语义并修正生日当天表达；统一配置中心及下级编辑界面的语言、紧凑行布局和弹窗层级；恢复完整的系统/浅色/深色界面外观支持；拆分输出页的照片说明并明确 iOS 系统支持范围；继续加固 Apple Photos 保存提交后的收据对账、队列恢复和重复输出保护。

本轮没有重建 IA-002 配置中心架构，也没有改变 Renderer、Layout Engine、Metadata、Share Extension、Commerce 或原始照片所有权。产品仍坚持本地处理，只生成新的结果照片，不修改 Apple Photos 中的原图。

## 产品与表达系统

### 时间锚点日历日语义

- 所有生产时间锚点路径统一按拍摄时区中的日历日判断关系；跨过本地零点即进入下一天，即使实际间隔不足 24 小时。
- 同一日历日内不再仅因具体时分早晚切换为倒计时；兼容路径的时、分、秒为剩余分量，并保持在 `0...23 / 0...59 / 0...59` 范围内。
- 生日锚点与照片拍摄时间位于同一日历日时，统一解析为 `onAnchor`。
- 简体中文完整表达改为 `{主体}今天来到这个世界啦！`，可复用年龄结果改为 `出生当天`，不再出现 `0天`。
- 英文完整表达改为 `{Subject} arrived in the world today`，可复用结果改为 `day of birth`，不再出现 `0 days`。
- 五种生日表达风格在锚点当天共用自然语句；各锚点类型在之前、当时、之后的专属表达文字保持不变。
- 兼容路径、设置内公式预览与主 Memory Expression 路径已同步，表达含义仍由 Memory Engine 和 Presentation 层持有，没有移入 SwiftUI 或 Renderer。
- 2026-08-06 之前，非生日锚点按精确时刻比较。该规则仅作为历史记录保留；未来如有类型确实需要精确时刻语义，应通过独立的类型级需求和验证计划重新评估。

### 界面语言

- 配置中心副标题调整为 `围绕一个人和一个重要时刻，决定照片如何呈现。`，更直接说明配置对照片结果的影响。
- 记忆来源保留用户熟悉的 `你想围绕谁开展回忆。`；配置卡片内的时间锚点副标题精简为 `回忆对象重要时刻`。
- `高级模块` 更名为 `更多信息`，说明聚焦地点与拍摄时间的显示方式；`区域内容设置` 更名为 `卡片内容`。
- 首页预设说明调整为 `下一次分享，照片会怎样呈现。`；首次设置操作由 `开始记录` 调整为 `完成设置`。
- 输出页面以 `新照片` 和保存位置说明结果，明确 MemoMark 创建新照片而不是修改原图。
- 简体中文、英文、可访问性文案、产品语言指南和源代码语言契约已同步。`记录`、`计算`、`生成` 改为按语境判断，不进行机械禁用。

### 界面外观

- 设置中的 `外观` 与 `界面语言` 收拢为同一个 `界面` 区域，两者使用一致的原生选择控件与辅助功能字号回退方式。
- 外观提供 `跟随系统 / 浅色 / 深色` 三种选择，默认跟随 iPhone 系统；选择会立即应用并在本地持久保留。
- 移除 iOS 根场景的全局强制浅色边界，应用页面、卡片、编辑行与弹窗改用系统语义背景和可适应深浅色的阴影。
- 真实 Memory Card、Classic White、Immers 白边、Logo 白色画布、Renderer 固定文字、照片裁切蒙层和主操作白色前景保持原有固定输出语义，深色界面不会改变生成照片。
- Share Extension 与系统照片选择器、分享面板等系统控制器继续遵循各自的 Apple 外观环境，没有引入自定义主题引擎。
- 外观偏好只在 iOS 主应用边界投影；macOS 没有因这次 iPhone 设置项被静默强制为相同外观。

### 输出页照片说明

- 输出页的 `新照片`、`照片说明` 与 `回到哪里` 拆分为三个同级卡片，统一使用现有标题、副标题、圆角、内边距、语义颜色与卡片间距。
- `新照片` 只保留照片格式、拍摄信息和 Live Photo 选项；现有照片说明预览、开关与条件输入框完整移入独立卡片。
- 照片说明继续复用 `usesCustomMemoryWriteText`、`customMemoryWriteText` 与 `resolvedMemoryWriteText`。完整右下记忆表达始终是基础内容；启用补充文字时，两段修剪后的内容以换行分隔，也不替换表达、不改写用户标点。
- 原先位于 iOS View 文件的组合器已移至非 UI 模型层；Configuration Session、iOS 预览、生产 Memory Module、Expression Context 与最终 Photo Description 使用同一来源，消除替换与换行两套语义。
- 照片说明开关的辅助文字在 Accessibility Dynamic Type 下允许换行；条件输入框展开遵循 Reduce Motion。共享卡片标题与配置中心分区标题会解析运行时本地化资源。
- 应用当前最低支持 iOS 18。iOS 18–26 继续依靠输出文件内的兼容说明元数据，Apple Photos 是否显示或索引这些信息由系统与资源类型决定，不能承诺一致。
- iOS 27 起 PhotoKit 提供直接的 `PHAssetChangeRequest.caption` 能力，但本轮没有接入。该能力需要后续独立处理可用性分支、资源身份、失败恢复以及静态照片与 Live Photo 真机回读。
- 卡片底部新增克制的版本差异提示；没有修改 Metadata Writer、Export、PhotoKit 保存事务或原始照片。

## 配置中心与下级编辑界面

### 紧凑行与右侧控件

- 配置中心的普通字号行恢复紧凑、单行优先的结构：标题说明位于左侧，按钮或选择器始终位于右侧并按整组内容垂直居中。
- 可见选择器采用紧凑 caption 字体和 `9pt / 6pt` 水平、垂直内边距，背景按内容自适应宽度，不再被 `44pt` 触控目标或 `128pt` 对齐列拉成宽大按钮。
- 右侧内容使用 `72pt...128pt` 的隐形对齐范围；选择器本身保持短小并右对齐。带说明或预览时，选择器与其下方内容组成一个整体居中。
- 普通 Dynamic Type 字号不再因 `ViewThatFits` 提前切换为上下布局；仅辅助功能字号使用垂直结构并允许完整展开。
- Logo 标识、时间锚点、记忆表达、更多信息以及可到达的记忆对象编辑入口已按同一紧凑行语法核对。

### 记忆表达预览

- 记忆表达选择器保持在该行右侧；原先附着在按钮下的预览移至该行下方的独立小型预览区域。
- 预览以更小、次要的文字展示当前表达在 `之前 / 当时 / 之后` 三个阶段的真实内容。
- 预览继续读取既有 presenter 的 `memoryDisplayDetail`，不在界面层重新计算时间或创作表达。

### 三个配置弹窗

- 时间锚点、更多信息和卡片内容使用原生居中的 inline 导航标题，并采用统一的居中 footnote 副标题、顶部节奏、水平边距和拖动指示器策略。
- 时间锚点副标题为 `选择一个时间起点，让照片拥有时间答案。`。
- 更多信息副标题为 `更多内容会根据实际需要逐步加入。`；其内容改为连续的 sheet 画布和一个紧凑条目面板，消除顶部与下方列表之间明显的底色断层。
- 卡片内容副标题为 `探索不同组合，也欢迎告诉我们你的自定义想法。`；四个区域在普通字号下恢复为一行一个区域，右侧只保留有辨识价值的简短预览。
- 三个弹窗共享面板填充、圆角、细边框、内边距、分隔缩进和最小交互高度，但根据内容密度保留不同 detent，不强制所有弹窗同高。
- 时间锚点新增/编辑页的名称与保存、类型与日期在普通字号下保持横向；记忆对象的表达主体选择器已移出头像旁的狭窄列，改为独立说明加右侧紧凑选择器。

## Apple Photos 保存可靠性

### TX-001 Slice 1：保存收据对账

- 静态照片与 Live Photo 写入器现在共用一套确定性的收据对账策略。
- 已记录的精确 `PHAsset.localIdentifier` 可见时，复用既有已提交资源，不创建第二份结果。
- 资源暂不可见时始终保留收据并等待；不再仅根据经过时间把不可访问或延迟可见解释为“未提交”，从而避免权限变化后出现重复资产。
- 新收据把资源标识与记录时间编码为一个 Codable 值后一次写入；旧版分离键仍可读取，并在迁移、删除和裁剪时清理。
- 查询只按已记录的 local identifier 直接进行，不扫描完整照片图库。
- 静态照片与 Live Photo 保存共用可响应取消的串行保存门；排队期间取消的任务会被移除，取得保存权后也会在进入 PhotoKit 外部写入前再次检查取消。
- 静态照片与 Live Photo 都使用 `photoLibrary.asset.readbackPending` 语义区分资源仍待可见的恢复状态，不把 Live Photo 延迟回读误报为结构损坏。

### TX-001 Slice 2：启动时队列对账

- App 启动时仅检查持久化在 `.savingToPhotoLibrary` 阶段的任务，并在一般恢复归一化之前执行收据对账。
- 收据所指向的精确 Photos 资源可见时，任务直接、持久地完成，保留同一资源标识，不重新渲染或再次保存。
- 资源缺失、不可见或结果有歧义时，带收据的任务保持在
  `.savingToPhotoLibrary` 对账状态，保留收据及已持久化的可恢复文件引用，
  不自动重新渲染、不清除收据、也不再次写入 Photos。经过时间本身不能构成
  “未提交”的证明。
- 后续前台或后台唤醒只会按同一 receipt 记录的精确 local identifier 再次查询；
  资源后来可见时才完成同一任务，不需要重启进程，也不会创建替代输出。
- `readbackPending` 保持在可恢复的 `.savingToPhotoLibrary` 状态，不写成终态失败，也不发送失败通知。
- 完成状态先持久化，再删除临时渲染输出和受管 intake 来源；持久化失败时保留文件以便恢复。既有免费额度终态转换规则保持不变。

## 代码结构健康

- `MemoryWriteTextComposer` 已从 SwiftUI 迁到共享纯逻辑文件，这是本轮唯一立即执行的结构拆分，因为它消除了真实的跨层 source-of-truth 冲突。
- `PhotoLibraryExportService.swift` 同时承担保存门、收据持久化、对账策略、权限、相册和写入/回读，仍是下一轮最高优先级的责任拆分候选；拆分必须保持 TX-001 行为和测试证据，不以文件行数为目标。
- `BatchQueueStore.swift` 继续保留 ADR-002 稳定 facade。启动收据对账可在 TX-001 稳定后提取为聚焦协作者，不改变外部队列 API。
- `MemorySubjectEditorView.swift`、`V1SettingsPageSurface.swift` 与 `V1ConfigurationOptionList.swift` 需要先做职责图，再决定是否拆分；当前没有仅因体积进行大范围重构。

## 架构与所有权边界

- 产品主路径仍为 `Apple Photos -> Share -> MemoMark -> Processing -> Notification -> Apple Photos`。
- `BatchTask.id` 继续作为一次逻辑保存事务的稳定身份；Apple Photos 继续拥有外部资源及其 local identifier；本地收据存储和队列持久层分别持有自己的恢复事实。
- Memory Engine 继续拥有时间与生命周期位置计算；Presentation 层继续拥有表达；Layout Engine 和 Renderer 的职责未变化。
- 配置中心仍为 `Library -> Interactive Memory Card -> Object Inspector`，本轮是 IA-002 内的语言和展示打磨，不是工作流重构。
- 没有新增网络、照片上传、图库全量扫描、权限、entitlement 或原图修改行为。
