## 本轮事实源

### 面向用户的交付语义

- 没有可呈现内容的单张照片不会再被当作成功结果保存或导出；该照片进入需要处理的失败状态，其他照片继续处理。
- 缺少 EXIF 或智能时间信息时，只要仍有用户文字或其他有效内容，照片仍可继续交付；元数据缺失不再被误判为整张照片失败。
- 批量通知从用户原始交给 MemoMark 的照片数量开始统计，不再只统计成功进入处理队列的照片。
- 重复项不会制造虚假的待处理数量；不支持的媒体、接收失败、处理失败、保存失败和验证失败会保留在需要关注的结果中。
- Share Extension 在照片已持久化但主 App handoff 尚未开始时，明确显示“照片已经接收，需要打开时光记继续处理”，不把排队成功误报为后台已经启动。
- 处理失败通知携带对应 Job 的 `memomark://processing/<jobID>` 路由；点击后进入处理状态并聚焦对应任务，避免用户只能自行寻找失败记录。

### 工程与边界

- `ResolvedContentValidator` 以最终解析后的 `CardTextBlock` 是否包含有意义内容作为交付前置条件。
- `BatchDeliverySummary` 统一表达 requested、completed、skipped、intake/processing/validation/save/verification failure 与需用户关注数量。
- `ExternalPhotoImportSummary.skippedRequiringAttentionCount` 区分合理跳过与需要用户处理的跳过，并对历史 JSON 缺字段保持保守兼容。
- 新增内容校验失败诊断，沿用既有 `JOB-` 支持编号和本地诊断边界；照片、原始文本、路径、地点和资源标识不进入诊断导出。
- 新增用户可见 handoff 与内容校验文案已进入简体中文和 U.S. English `Localizable.strings`。
- 本轮未恢复 Workspace、Dashboard 或 Import Flow，也未把批处理统计扩展成新的用户工作台。

## 应用内“更新日志”事实源

本次维护进一步明确照片交付状态，让每张照片的处理结果都能被看见。

- 没有可呈现内容的照片不会被保存成空白的成功结果。
- 批量处理会从你交给时光记的照片数量开始说明完成和需要处理的数量。
- 处理失败时，可以从通知直接进入对应的处理状态；单张照片需要处理时，不会拖住其他照片。
- 照片仍在设备本地处理，原图保持不变；完成后生成新的记忆照片。

## In-app “What’s New” fact source

This maintenance update makes each photo’s delivery result easier to understand.

- A photo with no presentable content is no longer saved as a blank successful result.
- Batch results now start from the number of photos you gave MemoMark, clearly separating completed photos from those that need attention.
- When processing needs attention, a notification can take you directly to the related processing status; one photo does not block the others.
- Photos remain processed on device and originals stay unchanged; MemoMark creates a new memory photo when finished.
