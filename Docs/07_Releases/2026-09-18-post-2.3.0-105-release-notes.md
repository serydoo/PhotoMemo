## 主要优化与维护内容

### 1. Configuration Center 跨平台收口

- macOS Configuration Center 继续采用 Apple 原生的横向卡片、真实 Memory Card
  预览和右侧 Inspector 编辑结构。
- iOS 与 macOS 共享配置会话、草稿投影、保存门禁和本地持久化边界；平台差异被
  保留在各自的表面层，不另建第二套配置真值。
- 设置、表达方式、外观、语言、输出位置和 FM 控件统一使用系统单选语义，保留
  44pt 触控目标、辅助字号回退、辅助功能值和既有权益保存逻辑。

### 2. FilmMark 从视觉修补推进到独立生产关系

- FM 使用独立的内容、外观、位置和布局规格，不再把旧 `TemplateArea` 兼容载体
  当作 FM 的长期语义真值。
- FM 生产快照同时携带独立内容与外观载荷；缺失或损坏的冻结载荷失败关闭，避免
  Share、批处理和重启恢复时生成不完整输出。
- `FilmMarkPresentationResolver` 统一内容解析、测量、布局和呈现结果，预览、静态
  导出和 Live Photo overlay 共享不可变的解析结果；Renderer 保持绘制职责。
- CoreText fit、画布坐标桥接、底部锚点、安全区域和底色衬托的几何关系得到契约
  测试保护，预览与导出仍使用同一套布局真值。

### 3. FM 配置界面与代码结构整理

- FM 控件、外观控件、位置/详情内容、配置支持、预览表面和详情 sheet 已按行为
  边界拆分，降低单文件集中度，同时保持 Configuration Session 作为唯一状态源。
- 预览中的安全边界与锚点提示仅存在于配置界面，不进入导出图、照片说明或无障碍
  语义。
- 四种本地化资源同步覆盖 FM 的颜色、字号、位置、重置、底色、空状态、时间/地点
  和辅助功能说明；资源键集合与格式检查继续作为自动化门槛。

### 4. 持久化、队列与兼容性保护

- 配置库继续使用 primary / last-known-good、revision 防覆盖、校验和与身份校验，
  旧 key 和 SchemaV1 兼容读取不被本轮删除或重命名。
- Batch queue 的 durable ledger、receipt reconciliation、迁移失败保护和幂等
  语义保持独立；FM 不创建第二个持久化真值。
- Classic White、Minimal、Apple Photos 原图保护、Share 路由和既有输出目标未被
  本轮 FM UI 整理改写。

## 验证边界

已记录的本地证据包括：完整 `MemoMarkTests` 通过（1,865 passed / 0 failed /
1 skipped 的最新综合记录）、macOS Debug、通用 iOS、Share Extension 构建通过，
治理检查与 `git diff --check` 通过；签名 iPhone 17 Pro Max 包曾完成覆盖安装并
启动，但这些证据不等于用户手工完成了视觉、Dynamic Type、VoiceOver、Photos、
Share、Live Photo 或重启恢复验收。

仍保持开放的证据门：

- TX-001：真实 Apple Photos 外部提交后的进程中断、精确读回与重复输出防护。
- BP-001：高分辨率单任务峰值内存、并发和导出延迟实测。
- 真机上的 FM 长文本、宽高比、辅助功能、保存重开、静态照片与 Live Photo 路径。
- COS 新鲜、可归因的当前工作区独立复核；本检查点不把旧会话或本地代码审查冒充
  为本轮新 COS 结果。

## 用户数据与平台边界

MemoMark 仍是本地优先应用：不上传照片、不覆盖原始照片，输出为新记忆照片并按
既有策略保存回 Apple Photos。源码检查点、GitHub 备份和本地构建都不改变这一承诺，
也不替代 Apple Photos、Share、通知和 StoreKit 的真实环境证据。
