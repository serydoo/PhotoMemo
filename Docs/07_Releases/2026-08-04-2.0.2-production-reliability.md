# MemoMark 2.0.2 版本更新说明

版本：`2.0.2 (68)`
日期：`2026-08-04`
定位：V4 阶段工程可靠性与兼容性维护版本

## 本次重点

### 1. 配置中心与模块兼容

- 模块改用稳定身份保存，旧配置恢复时不再因为内部名称变化而丢失标题。
- 配置恢复和预览现在支持组合变量，避免出现内部英文模块名或
  `{{variable}}` 原始占位符。
- 配置中心、预览和最终输出共用模块身份、展示名称与渲染令牌。
- 模块标题统一通过双语本地化目录提供，减少重复的硬编码中文目录。
- 自定义内容仍按用户原文保存；内容超出预览区域属于显示适配问题，不会直接造成配置保存失败。

### 2. 保存失败与处理异常可定位

- 配置保存失败会显示具体原因、恢复建议和 `CFG-` 支持编号。
- 图片处理失败会显示处理阶段、具体原因、恢复建议和 `JOB-` 支持编号。
- 新增本地结构化诊断记录，支持从“设置 -> 反馈”导出脱敏诊断文件。
- 诊断文件不包含照片、用户填写内容、位置、文件名、路径、资产标识或完整系统错误文本。
- 对超大图片、超宽/极端比例、无法解码、格式不支持、权限、存储空间、来源文件缺失等情况提供明确分类。

### 3. Live Photo 保真修复

- `originalFormat` 下，Live Photo 动态资源获取超时或恢复失败不再静默降级为静态图片。
- Share Extension 只拿到静态资源时，主 App 会保留 Live Photo 媒体真相；无法安全恢复就明确失败。
- 改名场景仅在拍摄时间和像素尺寸唯一匹配时恢复，多个候选不会猜测。
- 写入系统图库后回读验证 `.photoLive`、静态资源、配对视频资源、有效尺寸和动态时长。
- PhotoKit 未能保留 Live Photo 时不会报告成功，并写入专门诊断分类。

## 冲突核对结论

- 配置兼容改动只负责配置身份、恢复和展示投影；Live Photo 改动只负责媒体接收、处理路由和 PhotoKit 写入，未改变 Renderer 或 Layout Engine 所有权。
- 诊断机制只观察失败状态并保存脱敏事件，不改变照片原文、原始照片和本地优先边界。
- 旧的 `2.0.1 (67)` Commerce/Home 更新已保留在历史版本说明中，不与本次 `2.0.2` 的可靠性内容混写。
- 已同步修正应用内更新日志中“Live Photo 处理策略不变”的过时描述，以及项目、扩展和测试目标版本字段。

## 验证边界

- 专项 Live Photo、诊断、配置兼容和更新日志测试通过。
- 完整 `PhotoMemoTests` 通过：`1,221` 项通过、`1` 项跳过、`0` 项失败。
- macOS、iOS、Share Extension、Widget Extension Debug 构建通过，版本统一为 `2.0.2 (68)`。
- 真实 Apple Photos -> Share -> MemoMark -> Apple Photos 的 Live Photo 回环仍需在可用实体设备上验收；当前设备连接状态需恢复为可用后再安装。

## 产品边界

本版本不上传照片，不修改 Apple Photos 原图，不重建 Configuration Center，不改变 Memory Engine、Layout Engine、Renderer、Export 和 Share Extension 的既有职责边界。
