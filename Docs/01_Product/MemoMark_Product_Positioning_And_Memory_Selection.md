# MemoMark 产品定位与记忆选择原则

Last updated: 2026-09-18
Status: Current product principle
Owner: Product Loop
Scope: MemoMark 的长期产品定位、Apple Photos 边界、用户选图权和记忆输出模型

## 一句话定位

> Apple Photos 保存所有照片；MemoMark 帮助用户把真正想留下、想反复回看的照片，补上属于那段人生的时间和表达。

更完整的定位是：

> MemoMark 是一个本地优先的 Apple 记忆呈现系统。用户从 Apple Photos 中主动选出重要照片，围绕记忆对象、时间锚点和自己的文字补足照片的记忆语义，生成新的呈现结果并保存回 Apple Photos，同时保持原始照片的独立性。

## 产品关系：Apple Photos 与 MemoMark

MemoMark 不重新建立一个更聪明的图库，也不替代 Apple Photos 的照片管理能力。
两者的责任边界是：

| 系统 | 主要责任 | 不应承担的责任 |
| --- | --- | --- |
| Apple Photos | 保存、搜索、浏览和管理完整照片资产，以及系统相册和媒体能力 | 不需要理解 MemoMark 的记忆表达语义 |
| 用户 | 决定哪张照片重要、为什么值得留下，以及最终如何表达 | 不应被算法替代记忆判断 |
| MemoMark | 为用户选出的照片补充时间、关系和个人表达，并生成新的记忆呈现 | 不建立第二图库、不自动替用户决定人生记忆 |
| 指定 Apple Photos 相册 | 沉淀用户整理完成后的记忆集合 | 不应被描述为 MemoMark 私有图库 |

日常路径仍然是：

```text
Apple Photos
-> Share
-> MemoMark
-> Processing
-> Notification
-> Apple Photos
```

Configuration Center 负责长期配置和呈现校准，不是用户每天浏览全部照片的替代图库。

## 用户拥有最终选图权

MemoMark 的基本前提是：

> 用户先决定哪些照片值得留下，MemoMark 再帮助这些照片变得更完整、更容易回看。

一张照片的记忆价值不等同于清晰度、构图、相似度或算法评分。技术上不完美的照片，
可能因为一个表情、一个人、一段关系或某一天的背景而不可替代。

因此，MemoMark 当前不把“AI 自动选出最值得留下的照片”作为产品主张。任何未来的
智能辅助，都必须遵守以下边界：

```text
Selection Authority = User
```

允许研究的辅助方向包括：

- 按时间、人物或场景帮助查找候选照片；
- 对相似照片进行分组，减少用户查找成本；
- 根据用户明确的条件提供候选集合；
- 在用户确认之前清楚标记“候选”，而不是“已替你选择”。

不应默认执行：

- 代表用户判断哪张照片最值得留下；
- 自动创建一个未经用户确认的精选记忆集合；
- 用算法评分取代父母或家庭成员的记忆判断；
- 自动生成用户没有亲自确认的完整记忆故事。

这是一条产品边界，不代表当前已实现或已授权任何 AI 功能。

## MemoMark 补足什么

Apple Photos 已经保存照片的拍摄时间和大量系统信息，但回看时，用户仍可能需要
点击详情、重新计算或重新回忆照片在人生中的位置。

MemoMark 的作用不是把所有 metadata 都印到照片上，而是让用户主动选择的、适合
长期回看的记忆语义成为呈现的一部分，例如：

- 记忆对象和关系；
- 时间锚点与照片拍摄时间之间的距离；
- 年龄、成长阶段或纪念日关系；
- 用户自己的文字；
- 适合回看的地点或照片说明。

智能锚点提供准确的时间结果；用户仍然决定最终句子、语气和要不要加入这段表达。
MemoMark 不替用户书写他们没有确认的情感意义。

理想的回看结果是：用户打开指定相册后，照片已经能直接说明它在那段人生中的位置，
不必每次点击详情，也不必再次等待 MemoMark 计算。

这描述的是用户结果，不是对所有 Apple Photos metadata 显示方式的技术保证。照片说明、
搜索和系统展示仍受 PhotoKit、媒体类型和系统版本能力影响，必须按现行契约准确表述。

## 长期数据模型：源资产、记忆状态、派生呈现

MemoMark 应长期保持三种事实的分离：

```text
Source Asset
    -> Memory State
    -> Presentation Projection
```

### Source Asset：原始资产

原始照片和受支持的完整媒体关系属于用户的 Apple Photos 资产。MemoMark 生成新的
输出，不覆盖原始像素，也不因为输出为 JPEG 或 HEIC 就推导出 RAW、DNG、HEIC 或
Live Photo 原始资产可以删除。

### Memory State：记忆状态

记忆状态包括用户的选择、Memory Subject、Life Anchor、Time Anchor、用户文字、地点
和其他已经确认的记忆语义。它是可以继续补充和修订的状态，而不是导出文件中的一次性
字符串。

### Presentation Projection：派生呈现

记忆卡片、静态图像或受支持的配对媒体输出，是依据某一时刻的记忆状态和 Preset
生成的呈现投影。切换 Preset、补充信息或修正配置时，未来可以重新呈现；重新呈现
不能破坏原始资产或未经用户确认地改写记忆状态。

这意味着：

> 导出的照片是当前记忆状态的一次可保存呈现，不是唯一的业务事实来源。

## “哪里缺失，就从哪里补充”

MemoMark 不是一次性水印生成器。用户可以分阶段完成同一段记忆：

```text
今天：知道照片拍摄时宝宝 3 个月 12 天
以后：想起那天是第一次去外婆家
再以后：补上一句当时真正想留下的话
```

因此产品应支持这样的长期理解：

- 今天只补充时间，仍然是有效的整理；
- 以后补充地点或文字，不代表之前的输出失去意义；
- 新的记忆信息应进入可维护的记忆状态，而不是只能写进不可追溯的成品图；
- 重新呈现应以用户确认的状态为依据，并保持版本、任务和原始资产边界清楚。

这是一项长期产品和架构方向，不授权当前直接重做导出、持久化或 Share/Batch 契约。
涉及实现时必须遵循现有 V4 工程门控和相应的迁移、验证计划。

## 指定相册与打印的定位

指定相册的意义是：

> 用户主动选择、补充并整理完成后，愿意以后重新打开的记忆集合。

它不是 MemoMark 自动挑出的“最佳照片库”，也不是 MemoMark 自己拥有的第二图库。

打印属于下游消费方式之一。完整产品顺序是：

```text
拍摄
-> Apple Photos 保存
-> 用户选择
-> MemoMark 补足记忆语义
-> 保存到指定相册
-> 持续补充和回看
-> 需要时打印、分享或制作照片书
```

MemoMark 不应围绕一次处理大量照片并立即打印来定义核心工作流。只要照片已经整理
完成，用户可以在未来任意时刻选择打印；回看本身就是完整的产品结果，不需要以打印
作为完成条件。

## FilmMark 的产品解释

FilmMark 可以被研究为一种更克制、更安静、适合长期回看的呈现方式：

```text
Classic
= 信息记录和时间表达更清晰的记忆卡片

FilmMark
= 更少打扰画面、更适合慢慢回看的记忆呈现
```

这是一条 V4 产品研究方向，不是对 FM 生产完成度的声明，也不授权绕过 Product
Design Review、Engineering Gate、真机验收或现有 Renderer/Layout/Export 契约。

## 明确不做什么

除非未来形成新的、明确接受的产品决策，MemoMark 不应被描述或设计成：

- 第二个照片图库或照片管理器；
- 替用户自动挑选人生中最重要照片的 AI 工具；
- 云端照片服务或必须上传私人照片的记忆产品；
- 普通水印克隆或一次性批量图片工作台；
- 以批量打印为中心的生产工具；
- 自动替用户完成情感叙事的 AI 故事生成器；
- 一个把导出 JPEG/HEIC 当作唯一事实来源的系统。

## 后续产品判断清单

任何新的产品方向、宣传口径或界面流程，都应先回答：

1. 是否仍然由用户决定哪些照片值得留下？
2. 是否仍然把 Apple Photos 作为完整照片资产的所有者？
3. MemoMark 增加的是时间、关系和用户表达，还是重复建设图库能力？
4. 原始资产、记忆状态和派生呈现是否仍然分离？
5. 用户是否可以以后继续补充，而不是一次处理后失去维护入口？
6. 打印是否仍然是下游选择，而不是被动变成核心工作流？
7. 这项判断是否有当前 V4 场景和足够证据，还是只是一个吸引人的功能想法？

如果不能回答清楚，应先停留在 Product Loop 的观察或研究阶段，不进入代码、公开承诺
或生产能力声明。
