# 完整源码同步脚本修正

Engineering Loop，P1：旧 launchd 每1800秒调用脚本，脚本使用整树暂存，可能把本地验证/私密配置一起提交，且没有完整源码构建和远端一致性门禁。所有者于2026-10-16明确要求按完整源码标准修正，同时继续本轮 GitHub 同步。

## 边界与决定

只修改开发工具，不改变 App、业务职责、工程 target、运行时依赖、版本或签名。旧已安装任务在修改前暂停并备份。默认定时模式只生成本地待同步清单，不修改 index/HEAD/远端；明确 sync 命令需绑定完整候选和验证回执。

回执记录基线分支/HEAD、全部发布文件SHA-256、full host测试/iOS归档/脚本测试的成功结果及其本地证据路径。脚本检查回执与实际候选、当前完整源树一致，新增/删除源码均纳入；远端必须仍在基线，index必须起始为空。不得以单一passed布尔值替代完整文件绑定。调用者仍应审查本地验证证据，JSON回执不是密码学签名或生产认证。

本地排除只针对明确的生成物、设备素材、凭证/本机配置；Research/工程文档逐项纳入。被忽略源码/未知顶层内容/排除目录内未另存的源码须阻止sync并列出，不能静默遗漏。Source/Tests内新资源保持构建输入属性，不按图片后缀粗暴排除；签名私钥和结果产物不得混入任何目录。新增文字检查凭证、本机绝对路径和真实设备标识。

暂存使用完整明确路径清单，随后git diff --cached --check、导出index、比对完整文件内容；不使用reset、clean、force push或整树暂存。失败保留现场；push失败保留本地提交并记录，不假装同步完成。安装脚本更新已安装runner和plist环境变量，定时任务恢复为prepare。既有日志/旧plist/运行状态先备份。

2. 用Python标准库实现计划和受门禁保护的sync，zsh入口保持薄包装；不嵌入在线凭证。
3. 更新安装器与说明，用脚本聚焦与完整测试、shell语法/plist检查验证，再替换本机任务并实际观察prepare不变更Git。
4. 补齐本轮候选清单后，执行本轮完整验证、精确提交和远端readback。App已通过的测试/归档证据在应用输入字节一致时沿用；工具增量用新测试证明，不宣称云端运行已成功。
