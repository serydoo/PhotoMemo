# 设置结构复审：突出时间锚点与智能表达

2026-10-15 用户补充：创意重点是“时间锚点决定智能输出的表述”，而非增加装饰。以下是下一步结构方案，本文件不表示整页结构已经实装。评分/更新/反馈/移除社区是当前独立实现范围，继续完成验证。

## 代码与截图定位

SettingsPageSurface 把开始使用作为默认展开独立卡，其余照片处理、数据安全、反馈、界面、关于放入同一个大容器。各区可以同时展开，多个几百点高的说明把真正的偏好操作埋入滚动。界面的摘要会重复“跟随系统 · 跟随系统”，未指明哪个是外观、哪个是语言。

GettingStartedSupportContent 同时承担品牌故事、机制入口、欢迎页重看和工作流教程。主张很有价值，但四个入口加说明均用相近权重；最能说明产品差异的时间表达入口被当作一个普通帮助链接。

SettingsExpressionGuide 已经按 AnchorType.allCases（生日、相识、婚姻、考试、自定义）、MemoryAnchorExpressionStyle.availableStyles 和之前/当日/之后组织公式。现有机制完整度高，不应该再造平行表达模型。它包含的是讲解公式/占位示例，不应冒充当前照片计算结果。

## 建议的页面层次

1. MemoMark+：保留现有权益、恢复购买等商业路由与权属。
2. 一个约80–110pt的特色入口：**时间锚点，让照片有了前后**。说明：生日看成长，纪念日看陪伴，未来日期看倒数。按钮 **看看照片会怎么说** → 现有表达讲解页。首页仅表达价值，生日/其他类型与三阶段详细演示留到子页；避免再次铺成长教程。数值与语句仅为明确标注的示例，真实计算沿用现有规则。
3. 界面偏好：外观和界面语言可直接发现；摘要明确“外观：跟随系统 / 语言：跟随系统”。系统Picker继续使用，不另造设置存储。长的“界面语言与输出语言区别”放到帮助说明/简短脚注，保留真实边界。
4. 使用与数据：**使用指南**、**照片与数据**两条导航。前者承接欢迎/工作流；后者承接当前输入格式、批次上限、EXIF缺失行为、原图与本地数据说明。根页不同时展开多段说明。删除应用的数据风险保留在数据说明页，不省略真实边界。
5. 反馈与支持：**问题与建议**（邮件+小红书，诊断为次级）及 **给时光记打个分**。不再有社区、QQ群、GitHub。评分入口常见可找，不以满意度预筛。
6. 版本与关于：当前安装版本、检查更新、更新日志；**时光记的故事**保留为低频阅读入口。版权/结束语轻量，避免再形成一张重卡。

小屏/iPad保持相同顺序与内容；iPad读栏收拢，不为设置强制双栏。更大字体允许纵向增高，不用固定高度把描述截断。首屏约束以系统字号、窗口和安全区实际验证，不承诺任意设备永不滚动。

## 时间表达如何讲得直观

先讲“你选择什么重要日子”，再讲“照片拍于它的之前、当日或之后”，最后展示“相应的语气/公式”。

| 时间锚点 | 设置页应让用户马上明白 |
|---|---|
| 生日 | 出生前可以期待，出生当天留下纪念，之后呈现成长/年龄 |
| 相识、婚姻 | 相伴关系的起点与经过的时长，措辞随类别/风格变化 |
| 考试、未来日期 | 事前可以倒数，事后切换为经过多久，不永远倒计时 |
| 自定义日子 | 以用户定义的日期与名称表达之前/当日/之后 |

精确边界：锚点类型/表达风格决定可用说法，照片拍摄日与锚点日期决定阶段及时间结果，主体称呼与输出语言共同参与完整句子。不能宣传为任意输入都由一个锚点决定；不引入云AI生成、不改Memory Engine或Presentation semantic truth。

## 增量实施顺序

先交付当前商店/反馈小增量，再以独立Presentation spec实现“特色入口+长说明子页化”，接入既有导航和内容。之后才精简子页讲解/做演示，不重排业务架构、不迁移持久配置。原有欢迎/教程/时间表达配置跳转必须可达且返回设置上下文；流程验证与读栏/大字号/语言测试均需保留。
