## Frozen behavior

| Horizontal / vertical traits | Navigation | Configuration arrangement |
|---|---|---|
| compact / regular | bottom tabs | stacked |
| compact / compact | floating rail | stacked |
| regular / compact | floating rail | stacked |
| regular / regular | floating rail | side by side |
| unknown / unknown | bottom tabs | stacked |

Preserve all unknown combinations using existing comparisons: regular width or
compact height selects rail; only regular width AND regular height selects split.
Scroll clearance remains 96pt for bottom tabs and 26pt for side navigation.
Page widths, safe areas, rail placement, Preview toggle, editor identity, selection,
ConfigurationSession lifetime, localized strings and native containers are unchanged.

## Apple capabilities and dependency direction

Reuse SwiftUI environment size classes, existing live viewport geometry and native
TabView/NavigationStack. The pure policies do not import UIKit or business engines.
The SwiftUI adapter maps optional classes into capabilities without model-name,
global screen or hinge-angle inference. ArrangementView, reserved regions and Duo
native bars are deferred until their own bounded runtime slice. No production
runtime dependency or third-party Skill installation is needed for extraction.
Existing local SwiftUI/testing/quality Skills and reviewed research suffice.

Flow: system traits -> AdaptivePresentationCapabilities -> NavigationPresentationPolicy
or ConfigurationContentArrangementPolicy -> existing views. AdaptivePageLayout owns
scroll/readable geometry only. NavigationPresentationPolicy owns chrome clearance.
No stored presentation model, observer, cache, actor or feature flag is added.
